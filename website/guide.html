DOCUMENTATION / GETTING STARTED

Your first SlideDeck.

Install the VS Code extension, write your slides, and present them.

01 / VS CODE

Install the extension

Use desktop VS Code 1.67 or newer. Download the extension, then install the VSIX in VS Code:

Download the VS Code extension ↓

  1. Open the Command Palette (Ctrl+Shift+P, or Cmd+Shift+P on macOS).
  2. Choose Extensions: Install from VSIX… and select the downloaded slidedeck.vsix.
  3. Reload VS Code if prompted. Open a trusted workspace to use the preview.

The extension recognizes .slidedeck and legacy .sdml files. If you have the old slidedeckml.slidedeckml extension, uninstall it to avoid conflicting file associations.

02 / WRITE

Write your slides

Create and save a file named talk.slidedeck anywhere in your workspace. Separate slides with ===:

{
  author: "Your Name"
  title: "My Presentation"
}
===
# Hello, SlideDeck
Your first slide.
===
## What's next?
- Write in **bold** and *italic*
- Share your ideas

The editor provides syntax highlighting, diagnostics, completion and snippets: type sdml- to explore them.

ADD AN IMAGE

Copy and paste an image

With VS Code 1.97 or later, save your SlideDeck file, then copy an image (for example, a screenshot) or an image file. Place the cursor in the SlideDeck editor and paste with Ctrl+V (or Cmd+V on macOS).

SlideDeck saves a copy in an img folder beside your source file and inserts a reference like:

![Image](./img/image-unique-name.png)

The generated filename is unique; existing images are not overwritten. Keep the img folder with your source file. The source must be a saved file on the extension host's filesystem. Regular text pastes are unchanged.

03 / PREVIEW

See your slides as you edit

With the SlideDeck file active, click Open Preview to the Side in the editor title bar, or run SlideDeck: Open Preview to the Side from the Command Palette. The preview follows unsaved edits and the editor cursor. Double-click non-interactive content on a slide to return to its source.

Use Edit layout to move images or styled blocks and resize images; use Draw and Save fragments to create saved annotation fragments. Save the source file to retain changes. See drawing and layout examples for limitations.

The preview is disabled in untrusted workspaces and loads reveal.js and other libraries from the internet. It shows an error when the current source cannot be compiled.

04 / GENERATE

Generate HTML

Click Generate HTML in the editor title bar, or run SlideDeck: Generate HTML. Choose where to save the HTML; the current editor contents, including unsaved edits, are used. Save a new source file first so relative assets can be resolved. Local videos are copied into an assets folder beside the HTML.

Open the generated file in a browser. It loads reveal.js and other libraries from CDNs, so internet access may be required.

05 / PRESENT

Start your presentation

Click Start Presentation in the editor title bar, or run SlideDeck: Start Presentation. SlideDeck generates HTML beside the source and opens a new Firefox window. If the HTML already exists, you will be asked before it is overwritten.

Choose another browser with the VS Code setting slidedeck.browserExecutable; adjust slidedeck.browserArguments if needed. Starting a browser requires a local VS Code extension host. In a remote workspace, generate the HTML and open it locally.

ALTERNATIVE

Build from source and use the CLI

To develop SlideDeck or use the command line instead, install Node.js 16 or newer, npm and Git, then clone and build:

git clone https://github.com/jdeantoni/SlideDeck.git
cd SlideDeck
npm install
npm run langium:generate
npm run build

Compile a file to HTML or start the separate browser editor and live preview:

node out/cli/main.js compile talk.slidedeck -o talk.html
npm run dev talk.slidedeck

To run the extension from source, open the repository in VS Code and press F5 to launch an extension host. See the README for more options.
